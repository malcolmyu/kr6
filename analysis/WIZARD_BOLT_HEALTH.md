The comparison found and fixed these differences:

- A ranged ban suspends target-position updates but retains the target ID. It does not permanently abandon an already flying wizard bolt, and a still-present, non-dead target can take its impact while banned. Tracking resumes after a temporary ban. Exceeding the strict128-pixel maximum permanently clears the binding.
- Original update re-resolves the target from store.entities each tick. Web bolts previously kept hurting a removed object. They now require current membership for tracking/damage and can resume when the same target returns before impact. Death/revival and removed/returning cases are controlled contract fixtures, not claims about ordinary first-three-stage enemy behavior.
- ignore_hit_offset now affects the tracking destination. Magic-penetration probability is evaluated with the native strict comparison. Even chance0 consumes a random draw before the damage roll. With draws0.9/0.1, a rank1 bolt rolls7 damage, whereas the old implementation incorrectly used the first draw and rolled9.
- Tower arrows, wizard bolts and main catapult projectiles enqueue their damage and resolve it in reverse insertion order at the end of RangedCombat's projectile phase. Raw rolls still occur before immunity rejection. The supported health subset checks ignore_damage/immune_to, clamps final dead HP to0 and awards each death once. Simultaneous lethal bolts and a synthetic no-kill/order case compare with the original health routine; the latter ends alive at1 HP with no bounty, demonstrating noncommutative queue order.
