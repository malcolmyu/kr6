# 火雨真实控制器、陨石与粒子

本轮补齐火雨在实际GameSession中的控制器、陨石、影子、火焰粒子与落地伤害/特效队列。此前独立技能模拟已有原版轨迹，但网页正常施法没有创建这些实际实体，而且在技能预更新阶段直接执行飞行和伤害。完整视频还原仍未完成。

原始源码为kr6/scripts_game.lua:31400和31517。控制器下一flush入场，在自身main创建第一颗陨石，间隔0.33秒生成后续陨石，循环最大meteor_count/cataclysm_count后再删除。基础配置是3颗陨石，控制器仍完成5次循环；没有把它缩短到3次。陨石下一flush入场，在自己的第一次main先创建粒子系统、再创建影子，然后立即执行第一次加速/移动。影子和粒子再下一flush入场，不能在它们尚未入场的第一帧直接显示影子。

每颗陨石保留自己的加速度、目标、初始高度、旋转与影子缩放。到达时先排队删除影子，位置落在目标，将粒子source_lifetime设0，再抽一次该陨石共享的伤害值，为范围内敌人创建伤害包；落地贴花/爆炸按源码顺序排队，陨石也排队删除，实际身体保留到下一flush。命中伤害在主脚本之后处理，代替原先技能预更新直接改HP。完整跨所有战斗家族的统一health逆序队列仍需继续核对，不能从这两个输入推断已覆盖所有同时命中组合。

新增rain-trail.json由原始ps_power_rain_of_fire和原版动画导出。FirebookTrailSystem扩展到rain种类，保留54/s发射率、0.9–1秒寿命、26FPS图集帧、区域宽高各6的半幅随机偏移、旋转与寿命的实际四次抽取顺序。粒子仍按上一轮补齐的统一Lua实体表顺序运行。source_lifetime=0在原始粒子阶段末检查，并不简单等同于命中时立即禁止当帧发射。渲染器使用独立rain命名空间，避免与英雄/塔粒子ID冲突；陨石动画使用原始sprite.ts0全局时钟及原版帧判断，影子显示取决于实际实体入场。

两组均检查完整全局ID/事件/队列/实体表/数量与最大值、随机调用、经济/生命/波次/败北状态，以及真实敌人/英雄/士兵位置、节点、目标、HP和待机时钟。没有将原版事件喂给网页。进一步的实际逐帧校验检查每组60个陨石位置/目标/旋转、57个影子位置/缩放，变化组2850个、固定组2820个粒子时钟/寿命/位置/旋转/alpha/scale/图集帧/draw_order。所有项目通过，且新增非零样本断言。

校验过程发现并修复了一项测试错误：最初新增块因脚本替换未命中而未执行，计数为0。实体/伤害与浏览器结果当时已通过，但不能据此声称逐帧动画已比较。修正后两组重新执行，实际得到上述非零样本，保留此记录，防止把空检查当作证据。原始导出还修正了只读快照把控制器的bullet字符串当作bullet组件的错误；这一问题不影响原始游戏运行逻辑。

命令为verify_native_sequence.mjs --rain及附加--constant，均已接入npm test。生产构建、完整原有测试与两组实际火雨门禁通过；逐帧校验修正后，又单独重跑两组完整输入通过。旧弓箭塔、援军、法师/投石车等7组完整原版门禁保持通过。

browser_rain_runtime.mjs通过真实技能键/画布点击检查：控制器先排队；控制器main排队陨石；陨石main执行飞行并排队影子/粒子；下一flush显示影子和火焰粒子；实际渲染帧/位置/alpha/scale与模型一致；3次落地与施放/命中声音请求；控制器、陨石、影子、粒子及渲染对象全部回收。空波次受控fixture，没有声称已经实际听音或完整视频验收。截图web-rain-native-flight-particles.png和web-rain-native-impact.png，飞行图已查看。
