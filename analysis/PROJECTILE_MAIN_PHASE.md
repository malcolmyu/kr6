# 普通弹体的主脚本遍历顺序

本轮将已注册的普通法师/投石车弹体接入各自实体的主脚本遍历位置，修正爆炸发生前后读取敌人位置的顺序。完整前三关至3-2、启动效果、实际声音和视频一致性仍未完成。

原版同输入运行的1353帧，投石车弹体487对四个敌人产生14、14、17、14伤害。网页此前为14、14、17、15，落点相同，均为(649,430)。最后一个敌人在该帧移动之前的位置代入已验证的衰减公式得到14，移动之后得到15。网页把普通弹体统一放到所有敌人移动之后更新，导致这次偏差。

改动：

- `RuntimeEntities` 增加普通弹体绑定。发射时按原队列分配实体，入场时将同一实体绑定到实际弹体模型。
- `GameSession` 在 `mainBindings()` 遍历到弹体时调用其更新，与塔、骑士、英雄和敌人的相应回调交错。
- `RangedCombat` 将弹体更新从尾部批量循环中提取出来。每帧记录已执行模型，已在实体位置执行的弹体不再重复更新；独立组件调用和尚未接入注册表的弹体仍按其原有流程更新。
- 主脚本产生的普通弹体伤害仍在这次主脚本遍历结束后结算。不同攻击系统之间的全局伤害队列尚未统一，本轮没有声称已完成这部分。
- 对照延伸到1390帧时，发现原版逃出地图的敌人仍保留本帧实体，但已停止运动并请求下一帧移除。网页补上停速和删除队列请求。验证明确区分仍参与战斗的敌人和这个已逃出、等待删除的实体，并单独核对其位置、HP、逃出时间和删除请求。
