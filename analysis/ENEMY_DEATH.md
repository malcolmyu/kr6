# 四类常见敌人的死亡流程

本轮按原始 `SU.y_enemy_death` 和敌人主脚本补齐强盗、黑暗卫士、暗影弓箭手、暗影之刃的普通死亡、爆炸、消散、吞噬，以及血迹和尸体淡出。完整前三关至3-2、启动效果和音画一致性仍未完成。

原版死亡流程不是在HP归零时立即切换动画：当前攻击/等待协程先按其规则返回，死亡主脚本才接着运行。攻击命中边界与动画结束边界也会影响返回时机。原脚本完成死亡动画后再启动3秒等待、0.3秒淡出，并禁止普通health删除计时覆盖这段淡出。血迹另有自己的1–5秒透明度变化和下一帧删除队列。

改动：

- 增加 `EnemyDeathSystem`，在敌人自己的实际main遍历位置执行死亡续程；补齐基础近战在死亡时退出等待、保留边界命中和完成动画后的等待。
- 在已有伤害结算路径记录同帧致死伤害类型位掩码，区分普通/爆炸/消散/吞噬和水面分支。死亡声音由死亡主脚本发出；普通击杀奖励仍在伤害结算时发出。
- 保存并更新路径朝向，普通死亡按原版heading选择翻转；水面动画保留原翻转。
- 为文字、血迹、消散特效和尸体的动态tween提供实际实体表顺序的回调。tween、timed阶段放在主脚本后、普通弹体health/pops前。其他攻击系统的全局health/pops队列仍未完全统一。
- 血迹与死亡特效使用原始图集、锚点和透明度；补导出 `game_animations.lua` 中5个血迹颜色别名（实际图集帧此前已在资源包内）。按下一帧插入及实际移除显示和清理。
- 死亡模型和对应渲染对象会在删除刷新后真正移除。三处旧战斗测试原本在40秒后要求尸体仍留在敌人列表，现改为检查真实击杀奖励事件、奖励与伤害结果；完整尸体保留/移除行为由独立原版对照验证。

原版实际强盗89在585帧死亡，586帧进入死亡并创建血迹128，587帧插入血迹；尸体699帧请求删除、700帧删除，血迹736帧请求删除、737帧删除。网页现按相同语义时钟执行这些流程。全局ID/遍历只验证到636帧，之后仍有其他缺失生命周期。

新开局捕获仍为2,055帧、4次投石车/12次法师射击、7,363个原版路径移动样本一致；该检查指定敌人状态和顺序，不能当作独立完整战局或视频验收。

六关固定策略结果为四胜两负：1-1胜（20生命，271.7秒）、1-2胜（1生命，148.167秒）、2-1胜（20生命，435.4秒）、2-2败（124.2秒）、3-1胜（8生命，676.033秒）、3-2败（115.333秒）。结果见 `enemy-death-playthrough.json`。这些是策略试跑，完整还原尚未完成。

下一步包括弹坑等静态贴花tween、未移植的死亡分支/敌人类型、完整英雄主脚本和统一伤害队列、终局时机，以及完整3-2和实际音画对照。原版完整运行导出新增的死亡、透明度只读字段不改变原3714个注册表事件。
