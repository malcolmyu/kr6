# 火炎法书粒子拖尾

依据原包 `all/systems.lua` 的 particle_system（insert2451、update2473–2769）和 `ps_firebook_wizard` 配置接入实际火球。完整反编译仍有既存 LJD IndexError，使用原始字节码和原始函数连续执行作对照，没有用猜测的 CSS 动画替代。

## 原版规则

- 火球主协程排队创建发射器，下一 tick 插入。发射器从跟踪弹体的位置和旋转取样，不随弹体的 hidden 字段停止生成。
- 配置 emission_rate30，实际条件为 `time-emit_ts > 1/30`。不能简化成每 tick 一个：浮点边界会跳过某 tick，并在之后一次生成两个。每次生成按未取整的 emission count 对上次位置和当前取样位置插值，再按取整后的数量推进 emit_ts/last_pos。
- 每个粒子仅抽取一次 `[.9,1]` 的随机生命周期。生成时继承弹体当前旋转，随后位置固定，没有额外随机角度或漂移。
- 原版 `A:fn` 以动画时间乘2实现60FPS，使用原始17帧 `wizardfireballtrail` 图集。粒子生命周期和动画时长独立；非循环动画停在最后一帧，不能提前把粒子删掉或自行增加透明度渐变。配置 alpha255、scale1。
- 弹体在命中帧仍供发射器取样，下一 tick 从实体表移除后停止发射。已有粒子继续到各自生命周期结束，最后排队删除发射器，再在下一 tick 移除。

`FirebookTrailSystem` 只实现这个具体配置使用的分支，不代表所有原版 particle_system 选项已经支持。`WizardFirebookRenderer` 创建真实 Three.js 图集精灵，按粒子状态设置帧、位置、旋转、大小和透明度，并在粒子/场景结束后释放。场景沿用当前单位/投射物分层；全局原版 render/SSO 排序尚未完成。

## 原始对照

`export_firebook_particles.lua` 使用原始 simulation、火球 main_script、particle_system 和 A:fn。只把图片查找接口换成返回所选图集文件名，保留原始帧选择算法；配置和动画从原包导出至 firebook-trail.json。初始化 TICK_LENGTH1/30，避免缺少正常运行时全局初始化的测试夹具错误。

每套48组、4,800帧、25,929粒子状态样本，覆盖两个出生时刻、三个飞行方向、三个固定随机值与一组变化随机序列、正常落地和提前移除弹体。比较每 tick 的随机数调用总数、发射器插入/停止/移除、emit_ts，以及每个粒子的出生时间、生命周期、位置、旋转、帧名、透明度、大小和 draw_order。

- 基础套：原始火球关闭 pop、没有目标，以隔离飞行/发射器。
- `--combined` 套：加入一个固定目标，运行原始 mod_lifecycle/main_script/health/pops/particle_system，连同实际范围爆炸、燃烧、落地字样比较 HP、字样和完整随机调用序列。目标的导航有效性在此明确设为 true；实际路径选敌另有4,212组 A 原始 oracle。这不证明任意多个发射器、其他技能/AI 或全局随机序列都已一致。

初次 combined 夹具漏设有效路径条件，原始火球协程报 path_db 未初始化，生成的失败夹具保留为 firebook-particles-combined-missing-path-fixture.json。补齐隔离场景的有效性条件并加入原始命中断言后重新导出通过，未为此改变生产伤害参数。
