## 原始依据

- `functions/bolin_hero_update.bytecode.txt`：main首次运行将基础枪击的bullet替换为skill_c.bullet，并在每次创建弹体时设置当前技能等级对应的damage_cap。
- `functions/bolin_skill_c_bullet.lua`：先按目标最大生命加伤，Boss/小Boss走另一比例；`damage_cap`原始行为是`math.max`，实际为最低伤害，不能按字面名称实现为上限。
- `functions/bolin_ray5_simple.lua`：继承原版射线脚本，首次main立即造成伤害并创建两种FX，当帧隐藏射线，下一次main显示，按未取整的1.1秒时长等待并排队移除。射线方向与长度使用固定发射终点；FX位置使用目标当前身体与hit_offset。
- `functions/bolin_vector_angleTo.lua`：原版使用平台atan2；与V8在输入(-43,140)上分别为-0.29799692359622143与-0.29799692359622149。
- `scripts/export_bolin_runtime.lua`：直接导出原版Boss/小Boss位标记；升级数值使用已导出的原始有序补丁，不另手写三档伤害表。

## 正式实现

`BolinController`在英雄首次main启用特殊弹体，仅修改该英雄自己的模板。`BolinNativeRuntime`实现真实弹体创建、入场音效、C伤害扩展、伤害队列、两项独立FX、隐藏/显示及移除。`BolinRenderer`使用原始图集和锚点，按原版排序、角度与长度提交射线。

当目标在弹体第一次main前从实体表移除，原版C函数直接返回false，没有清除弹体。最终网页同样保留该实体和默认显示状态，专项与浏览器都覆盖了这个行为，未加自动清理。

死亡链另外修正了复活当帧的积存经验结算。原版生命协程返回后继续调用成长逻辑；网页此前迟一帧消费队列，现已对齐。

## 专项边界与证据

测试存档通过正式`validateHeroUpgrades`，按skill_a → upg_a → upg_d → upg_b → skill_c合法解锁。为单独观察C，原版和网页均在第20帧将其他主动技能的disabled设为true。这是明确的受控输入，不是普通混战验收。初期只含skill_c的不合法准备profile已被替换，旧录制仅压缩保留为历史资料。

`scripts/bolin_c_chain_cases.mjs`定义25条同输入场景：三档、五种额外方向、移动目标、发射前后目标移除、三个眩晕时机、无目标、Boss/小Boss、小生命目标触发最低伤害、护甲、伤害免疫、天赋1及护甲组合、三档Boss/最低伤害与普通死亡复活。

每帧检查真实GameSession的实体表/ID/稀疏表状态、插入与移除队列、完整实体事件、随机调用、HP/经验/积存经验/等级、英雄动作/翻转/时钟/回血计时、命中位置、弹壳运动/补间、全部粒子及具名音效请求。射线缩放、时钟和隐藏状态逐帧严格比较。

平台atan2引起的纯绘制角度差允许最多四个float64 ULP，其他时间、伤害、随机、位置和队列保持严格比较；没有在生产逻辑中四舍五入或调整攻击边界。Chrome比较实际射线根节点的角度/缩放（1e-12），并检查实际图集帧、EXO部件、透明度、场景提交顺序和隐藏帧不提交。
