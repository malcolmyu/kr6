# 英雄近战主脚本、伤害阶段和漏怪终局顺序

本轮把英雄基础近战接入实际实体主脚本遍历和后续伤害结算，补齐原版命中特效的显示、动画与回收，并修正漏怪与败北检测的阶段顺序。完整前三关至3-2、启动、听感与视频一致性仍未完成。

原始证据包括 APK `all/script_utils.lua:2116` 的 `y_soldier_do_single_melee_attack` 字节码与实际协程、`all/systems.lua:2361` 的goal_line、`:268` 的level，以及 `all/game.lua` 中系统顺序。单次近战先播放出手声音，等待命中时机，再分配伤害实体和命中特效；伤害在health11结算。命中特效坐标取攻击者位置加按朝向翻转的hit_offset，而不是直接用目标位置。

网页原先在批量士兵更新中直接扣血。现在正常GameSession的英雄基础行为在其自己的main_script7实体表位置执行；出手时保留原姿势起点，命中时提交伤害，在health阶段应用护甲、免伤、致死与经验，并在后续pops阶段显示伤害文字。攻击结束与下一轮动作之间保留最后的攻击姿势，避免提前一帧切回待机。特殊英雄技能仍有独立控制器，不能据此声称完整英雄主脚本已移植。

命中特效采用真实的排队实体。创建当帧隐藏，下一帧插入后显示；timed8请求删除的当帧保留，下一帧同时清理模型、注册表和渲染对象。骨骼动画使用原版帧时钟。原先直接对较大的出生时间差做floor，在整数帧附近会选错图像；实际原版14个有效特效状态逐帧验证了这一修正。

实际战局后续第1390帧的差异并非伤害丢失：两笔bandit伤害均存在，但网页在较早的敌人主脚本位置先排队了漏怪删除。原版goal_line17在所有main/health/pops之后遍历实体，再扣命、给金币、排队删除。网页现在也在该阶段处理。原版level1在下一帧才看到生命归零并判定败北；该帧已启动的其余系统仍完成，包含投石车弹丸的首次粒子创建。网页此前在漏怪当帧就停止运行，漏掉了这些后续事件。

验证：

- 270组原始预选近战/health轨迹、6210帧、216笔待结算伤害，覆盖杰拉尔德两种基础攻击和泽菲拉基础攻击，3个出生时钟、左右朝向、3个随机值，以及普通/免伤/护甲/致死/失去阻挡资格。比较main阶段HP不变、待结算伤害、health后的HP、随机数消耗、出手声音和命中特效坐标。预先指定攻击，排除选招与完成流程；原版上一帧已经处理的伤害仍保留到下一次health清理，该检查只比较未处理的待结算项。
- 实际GameSession对照至1390帧：83个泽菲拉接敌/攻击/姿势/经验状态，三次起手1316/1351/1386，伤害8发生于1331/1367，14个注册命中特效状态的坐标、出生时钟、帧与删除请求均匹配。
- 实际GameSession与原始固定随机数第三关铁人模式败北运行的全部1391帧、1815个实体事件严格匹配，包括全局ID、创建/排队/插入/删除顺序、完整Lua实体表顺序、计数/最大值与挂起队列。没有读取原版事件来驱动网页运行。
- 同一输入下19736个存活敌人状态、4128个注册骑士状态，以及位置、HP、路径节点、波次、经济、生命和败北/暂停时机通过对照。1390帧零命但未败北，1391帧完成移除与当帧系统更新后暂停。
- 原版完整运行只新增命中特效frame/runs只读观测，normal1899与constant1815注册表事件保持不变。这仍是CPU资源替代下的原始逻辑执行，不代表原生GPU、声音播放或独立视频一致。

此处完整对齐的是一个固定随机数、指定操作的1391帧败北用例。不同随机输入、全关卡通关、完整技能/英雄与全局伤害交错、后续胜利与GUI时机、启动和听感仍需继续验证，不能将该用例等同于完整3-2验收。

构建和完整自动化测试通过。最新固定策略六路线结果：1-1胜20命/272.6333秒，1-2胜1命/146.8667秒，2-1胜20命/433.8333秒，2-2败131.0667秒，3-1胜5命/673.0333秒，3-2败116.1667秒。四胜两负不构成验收。存档和一次性引导行为保持；未新增战斗现场存档。

浏览器第三关静止敌人/空波次场景验证最后一像素到位等待、下一帧起手、出手音效请求、main与health阶段HP边界、原始命中特效坐标、实际骨骼动画帧率输入、排队隐藏/插入显示/删除请求保留/下一帧清理。未做实际听感验收。截图：[命中特效](web-hero-melee-first-strike.png)。
