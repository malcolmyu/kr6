# 四级法师混战：原版绘制队列、命中特效与动画帧

2026-11-16。本轮继续既有普通输入路线，不调整其资源、随机流、敌人、技能数值或结算。该路线自然败北；不替代整体通关或视频验收。

## 修正

- 普通投射物命中特效过去只在 RuntimeEntities 分配了无模型描述符，而显示层单独创建临时动画。现在 `GameSession.combat.onEffectCreate` 对非静态 tween 效果也建立真实 `nativeEffects` 模型，并绑定原实体 ID。显示层按实际注册表插入/移除控制可见性和生命周期，采用原 sprite 的 Z/Y/draw/X 排序。新路线逐帧另验证 5345 个已注册特效状态的实体身份、位置和源动画时钟。
- 同一帧、同一点的同名特效过去都通过 `.find` 匹配到第一个模型。实际原版路线第 4329 帧包含两个独立泽菲拉命中特效（1695、1697），具有相同位置与时间戳。现在显示回调只取尚未分配给其他视觉实例的模型，保持一对一对应。浏览器验证每个提交的原 sprite/EXO part 唯一，并要求选定的可见原特效不得漏画。
- 已注册的 atlas 特效过去按 `floor(age*fps)%count` 取帧，受浮点边界影响可能慢一帧且会重复循环。原爆炸第 5508 帧，实际 age×30=0.9999999999999432，原版 frame_idx=2，旧算法为第 1 帧。现在使用既有原版 `nativeAnimationFrame` 的非循环取帧并钳制末帧。浏览器直接记录实际 setFrame 名称，与原版 sprite.frame_idx 逐帧比较。

## 原始数据与验证

`export_native_scene_paint.lua` 继续运行实际 APK 原引擎 systems.render，导出真实 render_frames。增加源精灵的 frame_idx、prefix、animation、exo 标识；新路线对火球发射、卖塔烟尘和爆炸从插入起连续观察 34 帧，另外包含同名重叠特效时刻。原 EXO 末尾的空白帧通过对应原 EXO 定义判定是否有非零 alpha 的实际部件，避免将没有可画部件的原帧误报为漏画。

`native-scene-paint-firebook-mixed-particles.json` 共 210 个检查点、129 组初始抽样扩展到连续动画区间。`browser_native_full_battle.mjs --firebook` / `npm run test:firebook-battle` 使用同一合法存档和普通控制命令，独立运行实际 GameSession + Three.js renderer，检查：

- 完整 5809 个逻辑帧、10437 个实体事件、31339 次随机调用与资源/队列，直至自然失败；902 次有效引擎音效请求逐帧逐顺序匹配。
- 210 个真实显示检查点：35482 个提交的原帧、1976 个血条片段、61127 个 EXO 部件。原坐标、排序元数据及整个提交队列相对顺序匹配；EXO 部件保持连续。
- 火球弹体 29 个可见状态、火球拖尾粒子累计 836 个原粒子帧；两次卖塔烟尘累计 24 个显示帧（每次 12 帧），爆炸 21 个显示帧。烟尘、爆炸实际 atlas 帧名严格匹配源 frame_idx。
- 同名同位置特效分配为不同 ID；没有重复提交同一 sprite/part，选定原特效可见时均有对应提交。
- 最终真实失败 GUI 显示，原声音请求、结算资源一致，无页面或资源加载错误。

构建与默认 npm test 通过。既有完整通关 Chrome 回归（8699 帧至胜利，187 个画面检查点、40781 个提交原帧）和 C/传送 Chrome 回归（6223 帧至失败，119 个检查点、22688 个提交原帧）也重新通过。

## 限制与后续

绘制队列、选定动画帧与完整逻辑的对照仍不能证明全部像素、声效混音或视频操作一致。这条路线仍没有活跃燃烧帧；原版独立燃烧生命周期与冻结目标 Chrome 用例已有验证，普通混战里持续燃烧的完整对照仍需补齐。新增若干只读策略探测保存为独立 `firebook-mixed-*`、`firebook-one-wizard-*` 文件，不覆盖主路线：另一个塔位、提前卖塔、C 技能、法师折扣、单法师策略均未获得活跃燃烧帧，不作为成功验收。前三关到 3-2 的完整视频与听感目标保持未完成。
