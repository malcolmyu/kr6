# 泽菲拉弹丸粒子与骨骼命中特效回收

本轮接入原版 `ps_bullet_zefira`，并修复骨骼特效缺少动画结束时机的问题。完整前三关至3-2及实际视频、启动、音效一致性仍未完成。

APK `kr6/scripts_game.lua:7334` 的原始字节码与实际协程执行表明：弹丸第一次运行时创建并排队拖尾，下一帧插入；发射方向初始为0，在后续移动步更新为弹丸方向。粒子每秒60个，寿命0.1秒，采用三帧原始图集动画。即使寿命上下界相同，原版仍消耗随机数。源弹丸删除后停止发射，已有粒子继续存活，全部过期后请求删除粒子实体，下一帧刷新才移除。

网页复用已有粒子计算器，增加泽菲拉原始配置与主脚本回调，英雄与塔使用独立粒子实例。渲染键也区分两类来源，避免两个系统各自产生的粒子ID1串用同一对象。命中特效现在接收原始弹丸方向。场景配置导出器补充骨骼动画帧数与帧率，因而实际命中特效能够在原版timed阶段结束，而非永久留在实体表。

轨迹对照还纠正了一个近距离边界：当初始落点已在一次移动距离内时，弹丸第一轮主脚本直接结束，局部目标尚未取得，所以不排队伤害。此前网页在该情况下错误造成伤害。测试现在依据实际原版执行检查HP保持不变，而不是保留旧实现的断言。

验证范围：

- 原始主脚本与particle_system的180组轨迹，涵盖3个出生时钟、5个方向/距离、4种随机序列、静止/移动目标及提前删除，共16200帧、5728个粒子状态，位置、方向、帧、透明度、缩放、随机数消耗和回收均匹配。
- 实际GameSession按相同操作执行到1390帧，两次原版泽菲拉射击的26个有效发射器状态和112个粒子状态、全部排队及删除事件匹配。该检查在较晚的全局差异之后使用语义身份对应，不声称全局ID一直相同。
- 真实全局实体表、ID、创建/排队/插入/删除及挂起队列严格对照推进至1330帧。下一个差异是1331帧英雄近战伤害实体创建尚未接入全局注册表；不能通过填充ID修补。
- 原版完整运行新增的粒子字段为只读观测，两组运行仍为2782帧、3714个注册表事件。该运行由原始协程执行，但CPU资源替代不证明原版GPU或声音播放一致。
- 浏览器空波次受控场景验证发射器先排队再插入、原图集帧的实际材质/位置/方向/缩放，以及英雄与塔同时出现粒子ID1时拥有独立渲染对象；命中后粒子、实体、渲染对象全部清理。无页面异常或资源缺失。截图：[实际粒子渲染](web-zefira-native-particles.png)。这不是独立视频音画验收。
- 完整测试与构建通过。最新六路线策略试跑：1-1胜20命/270.7667秒，1-2胜1命/151.0333秒，2-1胜20命/435.7667秒，2-2败131.4667秒，3-1胜9命/674.1秒，3-2败116.1333秒。新增原版粒子随机数消耗会改变该策略的后续随机抽样，不能以策略胜负代替还原验收。
