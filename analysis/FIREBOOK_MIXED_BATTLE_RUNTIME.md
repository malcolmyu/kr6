# 普通 3-2 混合技能战斗与协程边界

2026-11-16。使用 APK 原引擎、合法存档技能树和普通 GUI 控制输入生成独立新路线。仍保留既有普通通关与 C 技能路线，本路线不是视频操作转录，也不是通关演示。

## 原始证据

`native-runtime-firebook-mixed-profile.json`：两位英雄各 6500 XP，A/B 与 upg_a/upg_d/upg_b；原始全局升级与技能 XP。初始资金仍是原版 600，未改血量、金钱、伤害或结算。

`native-runtime-firebook-mixed-input.json`：先建造三座投石塔与两座法师塔，依法师塔实际价格逐次升到四级；按原版退款出售两座投石塔，再购买两级火炎法书。角色移动、援军、火雨和敕令均走普通控制接口。原 GUI 的建塔、技能购买与卖塔操作由 `export_level_entity_bootstrap.lua` 调用原字节码按钮函数执行。选择音效属于 GUI 展示，不参与归一化模拟随机流。

`level-entity-bootstrap-3-iron-cleared-firebook-mixed-runtime-lcg104.json`：完整 5809 帧，10437 个创建/排队/插入/移除事件，31339 次随机调用，最终自然失败，剩余金币 28、生命 0。`verify_native_hero_profile.mjs --firebook` 对照每帧实体表、队列、资源、HP、位置、XP 与有关英雄/修饰器时钟，另严格核对买塔提示修饰器的真实目标实体 ID；完整事件序列相同。

原音效观察 `native-firebook-mixed-battle-sounds.json`，`verify_native_battle_sounds.mjs --firebook` 核对 902 个非空引擎声音请求。GUI 波次提示和失败声音另验证。声音名称、顺序与触发帧相同，不等于听觉混音已经验收。

## 实际修复

1. 杰拉尔德普攻命中边界改点。原 SU 单次近战协程先检查是否已到命中时间，只有未到时才在等待体中检查改点。现在本帧先完成到期伤害，再中断攻击并让出一帧，下一帧消费新集结点。新全战斗在第 3802 帧覆盖这个真实边界。
2. 泽菲拉远攻死亡衔接。原 SU 远攻协程一旦创建过弹道，死亡结束动画尾部仍返回“已出手”，英雄主脚本继续到 idle 后才 yield。新增 `HeroRangedCombat.resumeDeath`，保留出手时间戳、恢复暴击倍率，并在射击恰到期的死亡帧仍按原版先出手。出手前中断会撤销冷却，且不进入 idle。
3. 卖塔由 tower_upgrade 阶段结算。点击只标记；该帧原塔仍执行自己的 main。结算按原实体表迭代顺序处理，删除买塔提示、退款、排队替换塔基和移除旧塔，生成具有真实 ID 的卖塔烟尘（位置 Y+35）。同帧出售多塔不再按点击顺序替换。
4. 买塔提示通过原持久 towers 索引顺序创建，升级信号立即将修饰器的目标 ID 转到已排队的新塔，避免直到插入才更新。卖塔会删除原提示，由塔基后续重新创建。
5. 导出漏掉的 `explosion_small_KR5` 实体及 `explosion_KR5_big` 原始 21 帧动画；恢复它的可见效果和 timed 清理，避免无帧数导致实体永久留存。

## 独立协程回归

`export_hero_ranged_death_continuation.lua` 使用原远攻 wrapper、原 SU 攻击与原 idle，覆盖三个时钟起点、九个死亡时间、两种暴击随机值，共 54 条 / 2214 帧。`verify_hero_ranged_death_continuation.mjs` 对照返回分支、动画/时钟/循环、暴击因子恢复、弹道位置/伤害因子与随机数。原 wrapper 的目标选择已固定；网页额外的一次成功目标选择随机调用单独计数。六次边界发射和 34 次待机衔接均有覆盖。已加入默认 npm test。

## 范围与未完成项

本混合路线确有火炎法书施放、弹道和技能升级，但没有活跃持续燃烧帧；不能用它证明混战燃烧效果的全链路。持续燃烧已有独立原生实体生命周期 oracle 与浏览器冻结目标验证，仍需一条普通混战里真正持续燃烧的完整原引擎对照。新路线的整个浏览器绘制队列与听觉效果也尚未逐视频验收。前三关所有模式、启动、建设动画、音效及实际视频一致性的整体目标仍未完成。
