# Local progress and once-per-slot onboarding

User request (2026-11-15): remember new-player guides and overall progress between visits, including when a preview is closed before winning a stage. This explicitly changes the previous behavior that only skipped first-stage guides after a campaign victory.

`Progress.onboarding` is stored inside each existing `kingdom-rush-6.slot.N.v1` localStorage record, with the active compatibility mirror in `kingdom-rush-6.progress.v1`. It records stage1/stage2 entry introductions and comic2 separately. It does not add stage completion, stars, currency, tower rewards or hero unlocks. Fresh slots write an empty onboarding object; older used slots without that field migrate to stage1-seen, so existing zero-star previews no longer replay their guide. Completed old campaigns also infer their already-presented introductions. Deleting a slot creates a genuinely fresh onboarding state next time.

On successful campaign scene setup, the stage's introduction is marked seen immediately. The current first visit still plays its full original comic/tutorial/cinematic; revisits, restart or reload skip it even when the first visit ended midway. Failed loading does not mark a guide seen. Comic2 is marked only when the first victory's Continue starts its presentation; later victories go straight to the map. Recent stage/mode is also persisted and used to focus the returning map.

StageSetup receives actual campaign-completion flags separately from onboarding flags. A guide-seen flag skips the stage1 manual tutorial using the ordinary preparation branch (+70 gold in place of the free70-cost tutorial barracks), but an uncompleted stage1 still has only Gerald. This prevents the old replay branch from inadvertently introducing Zefira before earning the stage1 completion. Stage2's once-only introduction has its own flag. Existing first-visit/native-completed replay branches remain available.

Campaign stars, iron completion, hero XP, hero upgrades and selected tower/power loadouts already shared the per-slot progress store. XP now additionally saves when changed at five-second simulation intervals, when pausing, on pagehide, on document becoming hidden, and before component disposal; existing outcome/restart/quit/level-change saves remain. Reload rehydrates the saved XP. This saves persistent game progress, not an in-battle checkpoint: current wave, gold, units and built towers restart with the level.
