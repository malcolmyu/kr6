# 援军实际入场、主脚本、退场和统一粒子顺序

本轮围绕视频3-2实际使用的基础援军补齐整局调度。此前独立技能单测通过，但实际GameSession在点击时直接创建士兵，漏掉原版控制器，外观/名字抽取、入场、行动和退场顺序均有偏差。本轮保持原始数值与波次，移植这些行为。完整视频还原仍未完成。

原版来源：

- `kr6/scripts_game.lua:34410` 的power_reinforcements_control.insert先抽取外观并创建两名士兵（高级分支先建特殊士兵）；其自身是insert-only控制器。每名士兵再通过 `all/scripts.lua:1101` 抽取名字，性别取决于等级与外观，女名4个、男名6个。
- `kr6/scripts_game.lua:17252` 的士兵update在自己的主脚本首次执行时记录时钟，发spawned-reinforcement信号，等待淡入，再执行近战/回位/待机与回血。实际控制器在下一次flush入场，在同次flush中创建的士兵也会入场；不是笼统地让所有子对象多等一帧。
- `all/script_utils.lua:1065` 的淡入等待10/30秒；循环动画保留原时钟，tween使用实际浮点时间，完成时保留前一帧写入的alpha。
- 到期检查位于协程外层。已经开始的攻击先执行完，才检查持续时间；受伤死亡分支在到期检查之前。活着到期的士兵向当前朝向走50单位、反向tween淡出；透明身体留在实际实体表，直到health按死亡时钟回收。受伤死亡则保留攻击/拦截引用到主脚本处理，播放死亡动画并淡出。

实现使用真实RuntimeEntities控制器/士兵绑定、插入回调、各自main与tween/health阶段。原始近战共用的等待、命中、命中特效、已死目标引用和队列行为接入实际基础援军；没有用补抽随机数、调整伤害或省略尸体来匹配日志。高级特殊士兵继续保留原有入口和独立技能实现，这轮并未证明所有升级/远程援军分支整局一致。

重复施放还暴露出跨家族粒子顺序：同tick结束的ps_bullet_zefira和ps_tower_wizard_bolt_trail，原版按统一Lua实体表处理，网页此前固定先塔后英雄。FirebookTrailSystem现在拆出prepare/advanceOne，实际粒子系统在插入时绑定到真实trail，然后按统一粒子实体表顺序执行发射、随机寿命、插值和回收。独立API仍使用同一实现。原有两组1391帧和两组1800帧对照继续通过。
