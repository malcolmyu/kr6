# 静态贴花tween与特效删除顺序

本轮补齐弹坑等有限静态贴花的实体、透明度和删除流程，并修正特效阶段的遍历与排队顺序。完整前三关至3-2、启动和实际音画一致性仍未完成。

原版弹坑 `decal_bomb_crater_KR5` 的alpha关键帧是1秒255、2.5秒0，固定缩放1.2。到达末关键帧时请求删除，下一帧实体刷新才删除。此前网页只画了一个定时淡出的图像，逻辑实体没有相应的tween删除，导致637帧起实体表不一致。

改动：

- `StaticEffects` 为有限、无主脚本的静态图集效果提供原版关键帧更新，支持数值、向量、布尔值、多sprite与linear/step/quad/quad_out/sine插值。循环、反向、随机起点及控制器驱动的效果不混用此实现。
- 直接从原APK导出9种对应模板的高精度tween字段，避免旧通用JSON输出截短循环小数后，把结束边界推迟一帧。其余sprite配置继续采用当前运行配置。
- 普通战斗特效发出时创建实际模型并排队绑定到实体；按真实Lua实体表顺序更新tween。独立渲染器读取模型alpha、缩放、位置和角度，下一帧才显示，请求删除的本帧保留，下一帧同时清理模型、实体和渲染对象。
- timed效果原来按创建数组逆序请求删除，改为按原版实体表顺序。723帧多个特效同时结束时的请求顺序因此对齐。
- 非滞留弹体现在在自己的main更新结束时请求删除，而不是统一等到所有main结束；普通模型清理与已有粒子尾迹处理保持各自流程。780帧弹体删除与新粒子发射器创建的顺序因此对齐。
- 核对原APK `all/game.lua` 提取的 `game-system-order.json`：main7 → timed8 → tween9 → health11 → pops15，particle21、render22、sound_events23。纠正此前代码把tween放在timed之前的问题，1077帧的同帧删除顺序因此对齐。
