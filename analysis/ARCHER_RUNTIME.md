# 弓箭塔独立射手、箭矢入场与战役宝石

HTML/Vue/TypeScript/Three.js 版本继续使用 APK 的资源、波次及原始逻辑。这轮补齐弓箭塔的实体调度，并修正完整战役输入暴露的两处英雄协程衔接。完整前三关至3-2、启动效果、实际听感与视频一致性仍未完成。

原版 `kr6/scripts_game.lua:18610` 在塔首次主脚本中，为每个射手创建 `controller_archers_shooter`，排队到下一帧入场。四级基础塔分别有1/2/3/4个射手，各自运行19173之后的待机、射击等待与动画完成判断。现在这些控制器是真实 RuntimeEntities 绑定，按 Lua 实体表顺序执行；升级/出售时，在旧塔实际删除回调中回收其控制器。没有用虚假的ID占位或多抽随机数补齐表顺序。

塔以当前敌人位置做首次选敌；射手等待14/30秒后，以10/30秒路径预判重新找最靠前的合法敌人。两次查询均使用原版SSO格子顺序与LuaJIT不稳定排序。无目标时调用原版delay_attack公式，包含源码中的1e-6减项；此前遗漏这一项，让轮询逐渐晚了四帧。射手独立保存上下方向、左右翻转、射击时钟、循环状态和长待机计时；射击动画最后一帧会保留到后续动画启动，网页不再在28帧后自行换成idle。

射手创建并排队箭矢，下一帧实体插入时，才按当时目标的motion.speed计算预判、误差和抛物线初速度。箭矢第一轮主脚本先yield，随后在自己的主脚本位置积分、判断命中并排队删除。实际绑定的箭矢保留最后一帧实体/画面到下次删除flush。目标是否存在也查实际实体表，覆盖插入顺序中的目标删除边界。

落空箭头使用原版EXO贴花及tween：前2秒alpha255，随后到4秒淡出，再排队回收。StaticEffects/StaticEffectRenderer已支持没有main/mod/particle控制器的有限EXO贴花；保留原有静态atlas贴花行为。浏览器额外检查了真实发射的箭在目标移动后落空、创建EXO部件、实际alpha/opacity一致和最终回收。

完整战役输入同时暴露了独立的随机数来源：`all/systems.lua:681` 每波开始以 `km.rand_uniq` 从该波所有spawn中选择宝石携带者，钢铁则取最后若干spawn。选中的敌人出生时，再用rand_sign决定宝石数量的±20%波动。新增 `WaveGems`，静态人数/携带者数量/每波宝石值从原始wave_db/game_settings导出至 `wave-gems.json`；这些是关卡配置，网页没有读取运行轨迹决定结果。战斗中击杀宝石计数与原始运行一致；完整宝石奖励UI和长期钱包仍需独立核对。

1800帧后段还发现两处英雄边界，均按字节码修正：

- 泽菲拉远程攻击完成后，6979主脚本的控制流直接到idle/regen，不能同帧重新进入melee/GoBack。此前网页提前一帧拦住了敌人。
- 已开始的近战攻击会继续到动画完成，即使目标在命中后已经死亡；不能马上清空攻击并索取下一个目标。当前按前一次render写出的runs判断完成，在完成帧仍执行原本的外层yield。
