# 皇家敕令实际实体与高级分支对照

目标仍是 Vue + TypeScript + Three.js 完整还原前三关至 3-2，包括视频中的启动、音效、建设与战斗表现。本记录只说明皇家敕令及已发现的下一处缺口，不能作为完整目标验收。

基础技能现已使用真实控制器、塔增益、国王、地毯、范围贴花的入场、主脚本、tween 和移除回调。原始依据为 APK 的 scripts_game.lua:31714、31746、31816、31890、31975、1592、535、494；额外金币为 32002、32010。相关反编译文件在 analysis/functions，循环跳转反编译失败处以原始字节码和原函数执行为准。

控制器入场按原顺序创建增益，主脚本创建国王、地毯和范围贴花。增益入场立即乘塔伤害/射程；起始动画结束后才重置 modifier 时钟，循环动画保留起始 sprite 时钟，最后一秒淡出并在实际移除时撤销倍率。范围贴花第一次移除会被拒绝，先进行反向 tween，再实际删除。RuntimeEntities 支持返回 false 的移除回调，不会提前从实体表和 persistent list 删除。

骑士伤害同时修正：原版在抽离散随机值之前乘塔倍率，网页此前在抽取后乘倍率。已修正攻击开始时捕获的边界和后续伤害，不改波次、HP 或平衡。LuaJIT 支持小数随机边界，例如 math.random(3.5,7) 可返回 5.5；不能把边界擅自取整。曾怀疑随机包装器需要转换，经实际解释器检查已否定，没有修改包装器。

原版 GUI 的 got-gold 回调（sequels/game_gui.lua:1262）负责加额外金币；纯 simulation 本来没有安装 GUI 回调。导出器对有存档覆盖的输入执行提取出的原始回调，只替换 UI 控件，不替换金币计算。接线时曾因 Lua assert 返回多个值给 debug.setupvalue 导致回调错误，已修正为单值绑定，重导出的最终日志没有 ERROR；不能使用中间失败导出作依据。

- 全图塔选择使用完整实体表 pairs 的顺序；普通范围选择仍使用原始 persistent tower list 顺序。两种顺序不相同。
