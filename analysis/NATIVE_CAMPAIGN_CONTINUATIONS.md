The previous turn implemented archer C but the ordinary campaign comparison stopped at1715. The same legal-input differential harness was rerun before editing and reproduced that failure. Four production differences have now been corrected from original bytecode/function execution:

1. **Enemy blocker wait.** EnemyMelee used the transient `moving` pose; original `y_wait_for_blocker` reads persistent `motion.arrived`. Gerald can stop the walk pose during a yielding ranged/ability continuation without having arrived. The enemy must retain its slot wait in that situation. Conversely, original `soldier_move_to_slot_step` sets `motion.arrived=true` when the unit already equals a new slot position. Both the generic soldier/hero and knight branches now do so. The original30Hz enemy oracle adds cases where pose and arrival disagree:104cases/24960frames pass. The hero arrival oracle now starts with arrived=false and compares the original flag too:72cases/1400frames pass. Both seams were observed failing before their respective fixes.

2. **Arrow dodge/miss allocation.** At3979 the web assigned994 to a miss decal and995 to `pop_miss`; the original assigned994 to the pop and995 to the decal. The original arrow coroutine creates the dodge pop and requests its hit sound before its miss FX/decal branch. RangedCombat now preserves that ordering. `export/verify_archers_arrow_impact` runs120original impact cases across four archer ranks, land/water/ice and normal/dodge/active miss/dead/missing targets, comparing damage/effect/pop creation sequence and shared RNG. It failed before the fix and passes after. This isolates queue hooks and does not establish sound mixing; full-battle sound traces cover their own request scope.

3. **Gerald post-hit rally yield.** At8422 he interrupts an already-hit attack; at8423 the original moves while web waited. `time+1/30` yielded280.7666666666667, later than the actual8423*(1/30)=280.76666666666665. prepareGeraldRally now calculates the next actual tick as `(round(time*30)+1)*(1/30)`, matching the existing hit-boundary continuation. `export/verify_gerald_rally_attack` compares the original single-melee → one caller yield → rally continuation at all30tick residues over two epochs:60cases/3600frames. It failed at birth8/tick31 before the fix and passes after. Damage/attack selection is deliberately outside this isolated post-hit seam; the full campaign includes the actual trigger chain.

4. **Projectile insert before wave selection.** At8793 an original catapult insert consumes a rotation roll before the fifth wave selects its gem carrier. Web had only registered the projectile descriptor at insertion and consumed the rotation roll later, inside combat advance. Both runs had the same total draws at8793, but native selected gem carrier5 and web9; the first count discrepancy surfaced at8861. Wizard and catapult-family pending shots now materialize through the actual registry insertion callback, as archer arrows and first copies books already did. The standalone combat fallback uses that same insertion method. The original8793/8861 boundaries are locked down by the default `--mark --through=8862` campaign gate, rather than by an implementation-mirroring mock.
