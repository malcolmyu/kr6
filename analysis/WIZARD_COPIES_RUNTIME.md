# 备份抄本：实际技能链、菜单与完整混战对照

2026-11-16。四级法师塔 C“备份抄本”已开放实际菜单，三级各 160 金币、满级状态与出售退款沿用原始数据。技能从施法塔独立出首次书本、弹跳控制器、第二次书本、地面书本与普通法球。不是以显示动画代替伤害，也不依赖施法塔继续存在。

## 接入内容

- `WizardTower.onCopies` 对接 RangedCombat 的真实待插入表。在注册表插入槽里检查目标存在性、计算原预测/误差与抛物线，交给原健康阶段结算 50 伤害。投书插入与命中音效各在原阶段触发；目标未注册时拒绝插入且不播放插入音效。
- 首次书本命中或落空都排队创建 `controller_tower_wizard_book_bounce`。首次书本隐藏并等待原纸片尾部生命周期；控制器在自己的 main 槽先分配第二本书，再消费四次随机数，取原道路落点，排队自身移除。
- 第二本书使用原 bomb 路径、旋转/飞行、纸片与落地 decal，落地后排队 `aura_wizard_skill_c`。修正无隐藏半径投射物在插入帧被误隐藏的问题。
- `WizardCopiesRuntime` 接管自主控制器。地面书本按真实插入、own-main 与 tween 槽分别执行；每级 3/5/8 发，按原伤害区间生成普通四级法师法球。分配法球发生在空场散射随机数之前。无目标时法球仍飞向散射点；有目标 ID 但目标已经不存在时才拒绝。
- 原普通法球的已有运动/粒子/健康/命中特效继续复用，保留地面书本覆盖的 min/max，不叠加施法塔倍率或强加双手侧向冲量。所有模型有真实 ID、队列与移除事件，出售塔不销毁已排队或自主实体。
- `WizardCopiesRenderer` 绘制已注册的地面书本，使用原 sprite 排序、动态动画名/时钟、非循环帧与淡出透明度；两次投书使用原模板的全局初始动画时钟。纸片使用原 5/s、60 FPS、4.5333333333333332 秒生命周期与原排序规则。

## 原版完整链路对照

`export_wizard_copies_chain.lua` 在原 APK 引擎运行完整技能。安静波次、高血量固定敌人为隔离条件；普通英雄/士兵保持其原位置与运行，不把单位移出地图，也不读取网页状态驱动原引擎。跟随地面书或离开范围的位置控制分别输入两侧。与直接控制器 oracle 相比，这里包括真实 main、健康、粒子、tween、插入/移除与 Lua 实体表顺序。

`npm run test:wizard-copies-chain`：九组、5400 帧，逐帧对照全局 ID/计数/实体表/待插入与移除队列/随机调用，另检查目标 HP、投射物位置和地面书本动画/时钟/透明度。
